# Agents 批量启用与默认范围设计

## 目标

Agents 管理页支持选择多个 Agent 后批量启用或禁用。没有保存过启用偏好的 Agent 中，仅 Claude Code 与 Codex 默认启用，其他 Agent 默认禁用。

## 范围

本次改动包括：

- 在 Agents 列表中选择一个或多个 Agent。
- 选择当前筛选结果以及清空选择。
- 批量启用或批量禁用所选 Agent。
- 保留现有单个 Agent 的启用、禁用操作。
- 将未配置 Agent 的默认启用范围改为 Claude Code 和 Codex。

本次不包括批量更新、卸载 skills，也不改变 Agent CLI 的安装探测逻辑。

## 交互设计

每张 Agent 卡片头部增加复选框。点击复选框只改变选择状态，不展开或收起卡片；点击卡片其他区域仍沿用现有展开行为。

搜索与状态筛选工具栏增加批量操作区：

- “选择当前结果”选中当前搜索和状态筛选共同得到的全部 Agent，不清除此前已选择但当前不可见的 Agent。
- “清空选择”清除全部选择。
- “批量启用”和“批量禁用”只作用于已选择的 Agent，并显示选择数量。
- 没有选择时，两个批量操作按钮不可用。
- 批量请求进行中时，选择控件、批量按钮和单项启用按钮不可用，防止并发修改覆盖状态。

操作成功后，页面用接口返回的状态更新对应卡片，并显示成功数量。操作失败时保留原页面状态并显示错误。

## 默认启用规则

服务端使用 `claude-code` 和 `codex` 作为默认启用集合：

- `agent_prefs` 中已有记录时，以保存的 `enabled` 值为准。
- `agent_prefs` 中没有记录时，只有 `claude-code` 和 `codex` 返回 `enabled: true`，其他 Agent 返回 `enabled: false`。
- 用户之后通过单项或批量操作保存的偏好覆盖默认值。

这项规则也适用于以后新增的 Agent：新 Agent 默认禁用，除非明确加入默认启用集合。

## API 与数据流

保留现有单项接口：

```text
PATCH /api/agents/:id
{ "enabled": boolean }
```

新增批量接口：

```text
PATCH /api/agents
{ "agents": ["claude-code", "codex"], "enabled": boolean }

200 OK
{ "agents": ["claude-code", "codex"], "enabled": boolean, "updated": 2 }
```

服务端先完整校验请求：

1. `agents` 必须是非空字符串数组，并对重复 ID 去重。
2. `enabled` 必须是布尔值。
3. 每个 ID 都必须属于支持的 Agent；存在无效 ID 时返回错误，不写入任何偏好。
4. 校验通过后，在一个 SQLite 事务中写入所有偏好。
5. 返回去重后的 Agent ID、目标启用状态和更新数量。

前端提交当前选择的 ID。请求成功后一次性合并响应状态；请求失败时不进行乐观更新，因此不会出现页面与数据库部分不一致。

## 错误处理

- 空数组、错误字段类型返回 `400`。
- 包含未知 Agent 时返回 `404`，响应指出未知 ID，事务不执行。
- 数据库写入失败返回 `500`，事务回滚。
- 前端通过现有 toast 展示服务端错误，并保留选择以便用户重试。

## 测试与验证

服务端行为测试覆盖：

- 无偏好时 Claude Code 和 Codex 默认启用，其他 Agent 默认禁用。
- 已保存偏好覆盖默认规则。
- 批量启用和批量禁用会更新所有目标 Agent。
- 重复 ID 被去重。
- 空选择、错误的 `enabled` 类型和未知 Agent 被拒绝。
- 包含未知 Agent 的批量请求不会写入任何有效 Agent。

项目增加 Vitest 作为轻量测试运行器。前端将选择与状态合并逻辑提取为纯函数，测试覆盖选择当前筛选结果、清空选择、批量按钮禁用条件以及成功后的状态合并；本功能不引入浏览器端端到端测试体系。
